W/01

From gut-feel territory calls to a ranked, explainable target list

The problem

Commercial decisions — which areas to chase, how to price against the nearest competitor — lived in disconnected tables and tribal knowledge. No single screen showed our revenue, total market activity and the competitor footprint together.

What I did

  • Co-built a four-tab geospatial Dash app on Databricks Apps fusing internal revenue with market water & drilling volumes and competitor locations.
  • Designed a load-once, in-memory architecture — parallel Arrow-backed SQL at startup — so every filter and polygon redraw is instant, with zero per-click database load.
  • Audited an upstream ML opportunity score, found most of its inputs degenerate, and replaced it with a transparent four-component score a rep can argue with.
  • Built polygon-draw analytics: outline any area, get well counts, revenue KPIs, top accounts and competitor proximity in one round trip.
  • Cut a 77-second table render to under one second and compressed multi-MB payloads roughly 10×.

Stack

Python · Dash · Leaflet · Plotly · pandas · Shapely · Databricks Apps · Databricks SQL · Unity Catalog · GitHub Actions

Outcome

In production with the commercial team across Western Canada and rolling out org-wide, with US regions coming online.

One lesson

A score you can't explain is worse than a simple one you can.

W/02

From a daily email to a live operations command center

The problem

Operations leaders tracked a network of dozens of facilities through a static daily email and four disconnected systems. Nobody could answer “where does the network actually have capacity?” without manual reconciliation.

What I did

  • Built a multi-page Dash app — an interactive network map with per-stream KPIs and a per-facility hub — so the whole network and any single site are one click apart.
  • Designed an observed-capacity utilization metric (rolling P95 baseline, grain-matched to daily volumes) because rated capacities weren't available — naive peak-hour math understated utilization roughly 10×.
  • Merged two measurement bases behind one interface with provenance flagged in the UI — an em-dash beats a confident zero.
  • Parallelized warehouse queries with caching and pre-warming: cold page loads went from ~50 seconds to a few.
  • Made every data source fail-safe: a broken query dims one section with diagnostics instead of blanking the page.

Stack

Python · Dash · Plotly · Leaflet · Databricks Apps · Databricks SQL · Unity Catalog · OpenTelemetry · GitHub Actions

Outcome

In production with operations leadership and rolling out org-wide across the facility network.

One lesson

Encode a metric's limits into the UI itself — it earns more trust than one that just looks precise.

W/03

Turning disposal capacity into a bookable, auditable resource

The problem

Facilities take truckloads of oilfield water against hard daily limits, but commitments lived in phone calls and spreadsheets — sales couldn't see remaining capacity while quoting, operations couldn't see what was promised, and nobody could prove booked volumes actually arrived.

What I did

  • Built a full-stack booking platform — Flask API plus a framework-free single-page UI with separate sales and operations workflows.
  • Modeled capacity as a derived quantity, never a stored one: SQL views compute remaining room from effective-dated limits, confirmed bookings and walk-ins, so the number can't drift.
  • Designed around the real 07:00–07:00 operating day so overnight loads count against the right shift — provably DST-safe.
  • Implemented transactional-outbox notifications: messages queue atomically with each booking change, so a dead mail server can never break a booking and nothing gets lost.
  • Reconciled promises against reality: live truck tickets matched to bookings through name and well-identifier canonicalization.
  • Shipped as infrastructure-as-code with isolated dev/UAT/prod, an append-only audit trail and ~300 automated tests.

Stack

Python · Flask · Databricks Apps · Lakebase (Postgres) · Databricks SQL · Asset Bundles · GitHub Actions · pytest

Outcome

Live in pilot and heading for org-wide rollout — one source of truth for who's bringing what, where and when.

One lesson

When every conventional path is blocked, the winning design is the one that needs zero new permissions.
